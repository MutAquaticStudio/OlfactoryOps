# Local Docker Decommission (Checkpoint Playbook)

## Objective

After Cloud-native remote verification is available, remove local Docker dependency
for routine science/development and move builds/tests to GitHub + Cloudflare runtimes.

## Why now

- Worker and Pages builds are CI-driven.
- Scientific workloads are now expected to run from container registry pipelines.
- Local Docker should remain explicit troubleshooting only until this checkpoint is
  proven in a non-production environment.

## Precondition

Do not remove any local Docker resources until all checks below are complete:

- remote scientific container workflow exists and can run
- at least one non-production verification passes using remote artifacts
- migration/config checks pass on the checkpoint branch
- no active CI tasks requiring active local compose or legacy DB containers

## Safe cleanup procedure

Use `scripts/cleanup-olfactoryops-docker.ps1`.

### 1) Dry-run (required first)

```powershell
./scripts/cleanup-olfactoryops-docker.ps1
```

This prints what would be removed, with a count summary.

### 2) Apply removal (only with explicit approval)

```powershell
./scripts/cleanup-olfactoryops-docker.ps1 -Apply
```

This removes only resources matching OlfactoryOps workspace scope and keeps global
Docker state untouched.

## Protected scope

This checkpoint never deletes globally:

- unrelated containers/images
- external project volumes
- active non-OlfactoryOps networks
- build cache used by other teams

## Allowed scope in this branch

Typical removals only:

- stopped containers with `olfactoryops` naming tags
- local images generated by scripts in this repository
- legacy compose artifacts under `*olfactoryops*`
- local compose project artifacts tied to known workspace names

## Verification after decommission

1. rerun health checks that previously relied on local Docker containers
2. confirm CI verification and role/contract gates continue to pass
3. keep `README` and runbook checkpoints current with evidence links
